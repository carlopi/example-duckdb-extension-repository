example-duckdb-extension-repository

This is a DuckDB extension repository: a static site that serves signed DuckDB extensions, laid out as <version>/<platform>/<name>.duckdb_extension.gz. It exists to demonstrate how a publisher hosts a repository on their own domain and how DuckDB finds and trusts it.

Use it

The host carlopi.github.io points DuckDB here from https://carlopi.github.io/.well-known/duckdb-extension-repo.json, so the repository is created by naming the host, with no url to type:

CREATE EXTENSION REPOSITORY carlopi.github.io;
INSTALL inet FROM carlopi.github.io;
LOAD inet FROM carlopi.github.io;

Or, naming this location directly:

CREATE EXTENSION REPOSITORY example WITH PREFIX 'https://carlopi.github.io/example-duckdb-extension-repository';

Signatures

Every extension here is signed with this repository's key. DuckDB pins the public key when the repository is created and verifies each extension against it at LOAD. The key is published in .well-known/duckdb-extension-repo.json, and CREATE EXTENSION REPOSITORY reports its fingerprint, which should read:

Contents

  • .well-known/duckdb-extension-repo.json: the repository's metadata, with its url and signing key.
  • v2.0.1/osx_arm64/container.duckdb_extension.gz: the container extension (containers as external resources: ATTACH TO NEW TEMPORARY EXTERNAL RESOURCE container.postgres AS pg), DuckDB v2.0.1, macOS arm64, built from carlopi/duckdb-container at ba32f04 (stamped b0e3ff6110) and signed with this repository's key.
  • Try it (needs Docker, Finch, Colima, OrbStack or Podman on the machine; the three catalogs start in under a minute and go with the session):
    CREATE EXTENSION REPOSITORY IF NOT EXISTS carlopi.github.io;
INSTALL AND LOAD container FROM carlopi.github.io;
CALL container_engine();                       -- stops here with the reason when no Docker/Finch/Colima/Podman is around
ATTACH TO NEW TEMPORARY EXTERNAL RESOURCE container.postgres     AS pg;
ATTACH TO NEW TEMPORARY EXTERNAL RESOURCE container.ducklake     AS lake;
ATTACH TO NEW TEMPORARY EXTERNAL RESOURCE container.iceberg-rest AS ice;
FROM duckdb_databases();
CREATE TABLE pg.orders AS SELECT range AS id, 'customer ' || (range % 7) AS customer, (range * 3.5)::DECIMAL(10,2) AS amount FROM range(1000);
CREATE TABLE lake.orders AS FROM pg.orders;          -- PostgreSQL -> DuckLake
CREATE SCHEMA ice.sales;
CREATE TABLE ice.sales.orders AS FROM lake.orders;   -- DuckLake -> Iceberg REST
DETACH pg; DETACH lake; DETACH ice;                  -- the containers go with the session
  • v2.0.1/wasm_eh/inet.duckdb_extension.wasm and v2.0.1/wasm_threads/inet.duckdb_extension.wasm: the inet extension for DuckDB-Wasm v2.0.1, the core builds re-signed with this repository's key, stored uncompressed (GitHub Pages cannot send Content-Encoding: br).
  • v2.0.0/osx_arm64/inet.duckdb_extension.gz: the inet extension, DuckDB v2.0.0, macOS arm64, re-signed with this repository's key.
  • c323c78907/osx_arm64/inet.duckdb_extension.gz and c323c78907/osx_arm64/autocomplete.duckdb_extension.gz: and c323c78907/osx_arm64/httpfs.duckdb_extension.gz: inet, autocomplete and httpfs built for the development build c323c78907 of the branch that implements this, macOS arm64, signed with this repository's key.
  • scripts/sign-extension.sh: signs an extension and places it in the layout above.
